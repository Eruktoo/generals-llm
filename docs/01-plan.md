# Generals LLM — 项目策划

## 一句话

> 4 个 AI 在战争迷雾下各自做战略决策，逐轮推进，看谁能活到最后。

---

## 核心设计

### 不是 generals.io 克隆

| generals.io | Generals LLM |
|-------------|-------------|
| 实时拖动，秒级反应 | **回合制**，每回合 AI 思考 + 引擎执行 |
| 玩家手动微操 | LLM 做全军战略决策 |
| 对操作速度要求高 | 对战略质量要求高 |
| 真人 vs 真人 | AI vs AI，你可以观战或加入 |

### 节奏设计

```
┌──────────────────────────────────────────┐
│  第 N 轮                                  │
│                                          │
│  1. 引擎暂停，生成 4 份战场快照           │
│  2. 4 路并行调用 DeepSeek                │
│     ┌───────────────────────┐            │
│     │ 每个 AI 收到：         │            │
│     │  · 自己可见的地图       │            │
│     │  · 自己的军队分布       │            │
│     │  · 当前排名/军力       │            │
│     │  · 上一轮自己的决策回顾 │            │
│     └───────────────────────┘            │
│  3. AI 输出：全军移动指令集               │
│     「从 (3,5) 调 15 兵到 (3,6)」         │
│     「从 (7,2) 调 8 兵到 (8,2)」         │
│     「从 (1,1) 调 5 兵到 (2,1)」         │
│  4. 收集所有指令，注入引擎                │
│  5. 引擎一次性执行 X 个半回合              │
│     （X 由我们控制，暂定 6-10）            │
│  6. 前端回放动画                          │
│  7. 回到步骤 1                            │
└──────────────────────────────────────────┘
```

**一局时长**：~100 轮 ≈ 100×4 = 400 次 API 调用 ≈ ¥0.80

---

## 为什么单个 LLM 做不到这个效果

如果用一个 LLM 模拟 4 个玩家：

```
同一个人知道所有 4 个视野
→ 「我打我自己」
→ 「我在左边佯攻右边主攻，但其实右边也是我」
→ 失去信息不对称的核心魅力
```

多 agent 的核心价值就在于：**每个 agent 真的只知道自己的信息**。

## 技术架构

```
┌─────────────────────────────────────────┐
│              前端 (SPA)                   │
│  Canvas 网格地图 + 迷雾 + 军队动画        │
│  部署: generals.shuttlescope.org         │
└────────────────┬────────────────────────┘
                 │ WebSocket / REST
┌────────────────┴────────────────────────┐
│           游戏引擎 (Python)               │
│  地图生成 / 状态管理 / 移动逻辑 / 战斗    │
│  战争迷雾 / 视野计算 / 胜负判定           │
│  监听 player moves → 推进 N 半回合        │
└────────────────┬────────────────────────┘
                 │
┌────────────────┴────────────────────────┐
│          LLM Agent 层 (Python)           │
│  4 个独立 Agent，各自收到 BoardView      │
│  各自调 DeepSeek → 输出移动指令集         │
│  并行执行                                │
└─────────────────────────────────────────┘
```

---

## 疑点：会不会很慢？

| 阶段 | 耗时 | 备注 |
|------|------|------|
| API 调用 (4 路并行) | 2-4 秒 | 4 个同时调，取最慢的 |
| 引擎执行 X 半回合 | < 0.01 秒 | 纯内存计算 |
| 前端动画回放 | 3-5 秒 | 可调速 |
| **每轮总时间** | **~6-10 秒** | 用户实际感知 |

100 轮 × 8 秒 ≈ 13 分钟一局。可以接受。

## 接下来做什么

### Phase 1: 最小可行游戏引擎 (纯 Python)

不连前端、不连 LLM，先搭：
- 网格地图生成（12×12）
- 玩家生成 + 将军放置
- 军队移动 + 战斗
- 战争迷雾计算
- 一个最简单的随机 bot（验证引擎正确性）

### Phase 2: LLM Agent 接入

- 写 agent 层：把 BoardView 翻译成 prompt
- DeepSeek 输出解析：从自然语言 → 移动指令
- 4 路并行控制
- 回环测试（引擎→LLM→引擎）

### Phase 3: 前端

- Canvas 网格渲染
- 迷雾效果
- 军队动画
- 玩家状态面板

### Phase 4: 部署 + 调优

- Cloudflare Tunnel → generals.shuttlescope.org
- LLM prompt 迭代（让 AI 更聪明）
- 可选：你加入当第 5 人
